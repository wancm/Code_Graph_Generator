# Code Graph Generator（代码图谱生成器）

选一个 C# 代码库的文件夹，它用 Roslyn 把代码读一遍，画出一张**代码图谱**（code graph）：每个类型是一个框，每条线是"一个类型用到了另一个类型"。结果存成**一个 HTML 文件**，双击就能离线打开，也可以直接发给别人。

不用 AI，同一份代码每次生成的结果都一样。代码只在本机读，不会发到任何地方。

## 它能回答什么

| 问题 | 在图谱里怎么看 |
|---|---|
| 改了这个类型，会影响谁？ | 点这个类型，选 **Who it affects**：所有直接或间接用到它的类型变成琥珀色 |
| 这个类型用到了什么？ | 选 **What it uses**：它直接或间接用到的类型变成蓝色 |
| 哪些代码可能没人用了？ | 右边面板的 **No incoming references** 列表，类型右上角有红点 |
| 哪些代码只有测试在用？ | **Only tests use it** 列表，琥珀色点 |
| 这条线是在哪一行写的？ | 鼠标停在依赖列表的芯片上，会显示 `文件:行`（每条线最多记 3 处） |

## 怎么启动

```bat
cmd\startup.cmd
```

它会用 Debug 编译，然后打开窗口。也可以直接运行：

```bat
dotnet run --project src\CodeGraphGenerator.App
```

需要：

- Windows 10 或 11，以及 WebView2 运行时（Windows 11 自带）。
- **.NET 10 SDK**。不只是编译本程序要用：Roslyn 读别人的代码库时，要靠本机的 .NET SDK 跑 MSBuild。
- 窗口里的 Bootstrap 样式和图标来自 CDN，离线时窗口会少一些样式；**生成的 HTML 完全离线可用**。

## 打包给没装 .NET 的电脑（Release 版）

想把程序直接拷给别人用、对方电脑又没装 .NET，就运行：

```bat
cmd\build-release-run.cmd
```

它做三件事：

1. 先删掉旧的 `run\` 文件夹，免得上一次打包留下的旧文件混进来。
2. 用 `dotnet publish` 打出 **Release、win-x64、自带 .NET 运行时（self-contained）** 的版本，放到仓库根目录的 `run\` 里。运行时已经打包进去，所以对方电脑不装 .NET 也能打开窗口。
3. 检查 `run\CodeGraphGenerator.exe` 是否生成了。

输出放在 `run\`，不放 `bin\` / `obj\`：后两个被 `.gitignore` 忽略，`run\` 没有。目前 `run\` 大约 **183 MB、342 个文件**，单个文件都小于 50 MB（GitHub 单文件上限 100 MB）。

具体参数：`-c Release -r win-x64 --self-contained true -o run`，另加 `-p:SatelliteResourceLanguages=en`（只留英文资源，去掉 Roslyn 和 WPF 十几种语言的资源文件夹）和 `-p:DebugType=None -p:DebugSymbols=false`（不带 `.pdb` 调试文件）。

**为什么不打成单个 exe（single-file）？** Roslyn 读代码时，要从 exe 旁边的 `BuildHost-netcore\` 和 `BuildHost-net472\` 文件夹启动一个单独的 MSBuild 进程。实测打成单个文件后会报 `The build host could not be found`，什么代码库都读不了；按文件夹发布则正常。所以要把**整个 `run\` 文件夹**拷过去，在那边双击 `CodeGraphGenerator.exe`。

**对方电脑还需要：**

| 需要 | 为什么 |
|---|---|
| Windows 10 / 11（64 位） | 打包的是 win-x64 版本 |
| WebView2 运行时 | 窗口界面靠它显示；Windows 11 自带，多数 Windows 10 也有 |
| **.NET SDK**（光有运行时不够） | 打开窗口不需要，但点 **Generate** 读代码库就需要：Roslyn 通过 `dotnet` 启动 MSBuild（`BuildHost-netcore` 至少要 .NET 8），**Run dotnet restore first** 也是直接调用 `dotnet restore`。SDK 要能编译要读的那个代码库（看它的 `global.json` 和目标框架），例如读 .NET 10 项目就装 .NET 10 SDK。没有 SDK 时窗口能打开，但生成会失败 |
| 网络（可选） | 窗口的部分样式来自 CDN；生成的 HTML 完全离线可用 |
| Claude Code（可选） | 只有用 AI 描述功能时才需要 |

## 怎么用

1. 点 **Select folder**，选代码库所在的文件夹，例如 `C:\onecm\wcms`。
2. 程序会往下找 4 层，找出 `.sln`、`.slnx`。没有解决方案文件时改找 `.csproj`，多于一个时会多一个"All N projects in the folder"选项。找到几个就在 **Code base** 下拉框里选。
3. **Output file**：默认写到 `文档\Code graphs\{文件夹名}-code-graph.html`，点 **Change** 可以换位置。
4. **Run dotnet restore first** 默认勾上，一般别关（原因见"已知限制"第 1 条）。
5. 点 **Generate**。右边 **Progress** 显示进度，最新的在最上面，可以点 **Cancel** 取消。
6. 完成后显示类型数、线数、项目数和没人引用的类型数，以及警告（比如某个项目编译不过）。点 **Open code graph** 用浏览器打开结果，或点 **Show in folder** 打开所在文件夹。

窗口会记住上次选的文件夹、输出位置和 restore 开关，存在 `%LOCALAPPDATA%\CodeGraphGenerator\settings.json`：

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `LastFolder` | string | 无 | 上次选的代码库文件夹，下次打开时自动用它 |
| `OutputFolder` | string | `文档\Code graphs` | 上次用 Change 选的输出文件夹 |
| `RestoreFirst` | bool | `true` | Run dotnet restore first 的勾选状态 |

## 生成的 HTML 怎么看

| 控件 | 作用 |
|---|---|
| **Search a type** | 输入类型名，从下拉建议（`名字 · 命名空间`）里选，或直接按 Enter，就会跳到这个类型并选中它。打字时，名字里含这段文字的类型会描上蓝框 |
| **Group by** | Types：一个类型一个框。Namespaces / Projects：把同一命名空间或项目的类型合成一个框，线变成合并后的，线越粗代表合并的线越多 |
| **Neighbourhood depth** | 选中一个类型后，只显示离它 1、2 或 3 条线以内的类型（两个方向都算）。All = 全显示 |
| **Show tests** | 显示或隐藏测试项目的类型（灰色） |
| **Who it affects** | 影响分析：谁直接或间接用到选中的类型，即改了它可能坏掉什么。琥珀色 |
| **What it uses** | 依赖分析：选中的类型直接或间接用到什么。蓝色 |
| **Clear selection** / Esc | 取消选中 |
| **Fit to screen** | 把整张图缩放到刚好放得下 |
| 拖动 / 滚轮 | 平移 / 缩放 |
| 右边面板 | 没选中时：总数、No incoming references、Only tests use it、Entry point 三个列表，以及警告。选中时：类型种类、项目、命名空间、所在文件，直接（粗体）和间接的类型芯片，点芯片就跳过去 |

**大代码库**：超过 250 个类型时，图谱一打开就是按项目分组（只有一个项目时按命名空间分组），顶上会有提示。这时搜一个类型，图谱会自动切到 Types，并把 Neighbourhood depth 设为 2，只显示它附近的类型。

颜色和形状：每个项目一种颜色，测试项目是灰色，接口是虚线边框。右上角的点：红色表示 No incoming references，琥珀色表示 Only tests use it，绿色表示 Entry point。

## 图谱是怎么算出来的

用 Roslyn 的 `MSBuildWorkspace` 打开解决方案或项目，拿到每个项目的编译结果（compilation），然后把每个 C# 文件读两遍：

1. **第一遍找类型**：class、interface、record、record struct、struct、enum、delegate 各算一个点。partial 类型只算一个点，但会列出它所有的文件。嵌套类型单独成点，写成 `Outer.Inner`。顶层语句（top-level statements）算作编译器生成的 `Program` 类型。
2. **第二遍找线**：在每个类型的代码里，看每个名字指向的到底是哪个符号：

| 线 | 什么时候画 | 例子 |
|---|---|---|
| **Implements or inherits**（虚线） | 写在基类列表里的接口或基类 | `class SqlRepo : IRepository` |
| **Calls or creates**（实线） | 调用方法、属性、事件，或者 `new` 一个对象；Razor 页面里写 `<Badge />` 也算 | `repo.SaveAsync(x)`、`new Order(1, 2m)` |
| **Uses type**（点线） | 其他所有提到这个类型的地方：参数、字段、变量、泛型参数、`typeof`、`nameof`，以及读取字段或常量 | `List<Order>`、`OrderStatus.New` |

- 两个类型之间只画一条线，取最强的那种：实现 > 调用 > 用到类型。
- 不算线的：`using` 指令、注释和 XML 文档、类型引用自己，以及代码库以外的类型（.NET 自己的类型、NuGet 包里的类型）。
- **Razor 组件**：Razor 生成的 C# 里写着原始 `.razor` 文件的路径，所以组件的点指回 `.razor` 文件。`_Imports.razor` 只有 `@using`，跳过。
- **生成的代码**跳过：`obj\` 和 `bin\` 下的文件、`*.g.cs`、`*.designer.cs`、开头写着 `<auto-generated>` 的文件、源生成器的输出（Razor 除外）。
- **测试项目**：项目名以 `.Tests`、`.Test`、`.UnitTests`、`.IntegrationTests`、`.Specs` 结尾，或者引用了 xUnit、NUnit、MSTest、TUnit。

布局在 HTML 里用 JavaScript 现算：先把循环依赖断开，再按"使用者在上、被使用者在下"分层，然后反复按邻居的平均位置排序，减少线的交叉，太宽的层会换行。没有任何线的类型放在最下面一行。

### "没人引用"（No incoming references）怎么判定

一个类型如果没有任何其他类型画线指向它，就算 **No incoming references**，可能是死代码。只被测试项目引用的算 **Only tests use it**。下面这些算 **Entry point**，永远不算死代码：

- 程序入口：`Main` 所在的类型，或者顶层语句的 `Program`。
- 框架会自己找到的类型：
  - 带这些特性（attribute）的：`[Route]`（包括 Razor 的 `@page`）、`[ApiController]`、`[McpServerToolType]`、`[McpServerPromptType]`、`[McpServerResourceType]`、`[Migration]`、`[DbContext]`。
  - 继承这些基类的：`ControllerBase`、`PageModel`。
  - 实现这些接口的：`IDesignTimeDbContextFactory`、`IRequestHandler`、`INotificationHandler`。

测试项目里的类型本身不参与判定。通过反射、配置文件或其他框架约定被用到的类型，仍可能被误报。所以这个列表是"值得看一眼"，不是"可以直接删"。

## 已知限制

1. **代码库要能 restore**。本机装了好几个 .NET SDK 时，MSBuild 会按代码库文件夹的 `global.json` 选 SDK，没有 `global.json` 就选最新的（例如 11.0 RC）。如果代码库之前是用别的 SDK restore 的，Roslyn 可能连 .NET 自己的类型（`System.Object`）都找不到，而且不报错，结果大部分线都会缺。所以 Run dotnet restore first 默认勾上（它只会改代码库的 `obj\` 文件夹）。出现这种情况时，警告会写明是哪个项目。
2. **只支持 C#**。VB 和 F# 项目会跳过。
3. **看不到数据流**：只看代码里谁引用了谁。例如 wcms 里 `ChannelProducer` 往 channel 写数据，`ChannelConsumer` 从 channel 读，两者互不引用，所以图上没有线。
4. **看不到运行时的依赖注入**：只看到注册那一行（例如 `Program` 用到了 `SqliteContentRepository`），看不到运行时注入给谁。
5. **看不到跨服务的调用**：gRPC、HTTP、TCP、消息队列另一头的服务不在同一个代码库里。
6. **XAML 里的引用**（绑定、资源）不算，因为 XAML 生成的 C# 被当作生成代码跳过了。
7. 窗口的样式来自 CDN（见"怎么启动"）。

## 接口一览（REST / gRPC / TCP / MCP）

**没有。** 本程序是一个桌面窗口，不开端口，不提供任何 REST、gRPC、TCP 流或 MCP 工具，也不调用其他服务。它唯一启动的外部程序是 `dotnet restore`，以及 Roslyn 自带的 MSBuild BuildHost 进程。

## 生成的 HTML 里的数据格式

数据嵌在页面的 `<script>const DATA = …</script>` 里，需要时也可以用别的工具读出来：

| 字段 | 类型 | 含义 |
|---|---|---|
| `root` | string | 选的文件夹 |
| `source` | string | 用的解决方案或项目（相对路径） |
| `generatedAt` | string | 生成时间（ISO 8601，带时区） |
| `tool` | string | 生成器版本 |
| `warnings` | string[] | 警告，最多 30 条 |
| `projects[]` | object | `n` 项目名、`f` 项目文件（相对路径）、`t` 是否测试项目 |
| `nodes[]` | object | `n` 名字、`f` 全名、`s` 命名空间、`p` 项目序号、`k` 种类（class / interface / record / record struct / struct / enum / delegate）、`r` 引用状态（referenced / entry / test / testsOnly / unreferenced）、`l` 文件列表 `[[文件, 行]]`（行为 0 表示不知道） |
| `edges[]` | array | `[来源序号, 目标序号, 种类, 出处]`，种类 `i` = 实现或继承、`c` = 调用或创建、`u` = 用到类型，出处是 `[[文件, 行]]`，最多 3 处 |

## 项目结构

| 路径 | 内容 |
|---|---|
| `src/CodeGraphGenerator.Core` | 读代码和写 HTML：`CodeBaseFinder`（找 .sln/.csproj）、`DotnetRestore`、`CodeGraphBuilder`（Roslyn）、`ReferenceAnalysis`（死代码判定）、`HtmlGraphWriter` 和 `Html/GraphTemplate.html`（查看器，内嵌在程序集里） |
| `src/CodeGraphGenerator.App` | WPF 窗口加 Blazor（BlazorWebView），MyFav1 主题。页面：Generate（`/`）、Readme（`/readme`） |
| `tests/CodeGraphGenerator.Tests` | xUnit 测试 |
| `tests/Fixtures/SampleShop` | 测试用的小代码库：领域项目、带顶层语句的程序、Razor 组件库、测试项目，每种规则都有例子 |
| `cmd/startup.cmd` | 编译并打开窗口 |
| `cmd/build-release-run.cmd` | 打包 Release、win-x64、自带 .NET 运行时的版本到 `run/`，给没装 .NET 的电脑用 |
| `run/` | `cmd/build-release-run.cmd` 的输出（每次打包前先清空）；没有被 `.gitignore` 忽略 |

## 测试

```bat
dotnet test CodeGraphGenerator.slnx
```

共 22 个测试。其中 10 个会先对 `tests/Fixtures/SampleShop` 跑 `dotnet restore`，再用 Roslyn 真正读一遍，检查找到的类型、三种线、线的出处（文件和行）、Razor 组件和 `.razor` 文件的对应，以及死代码、入口点和"只有测试在用"的判定。

## 设计上的几个决定

- **Blazor Hybrid（WPF），不用 Blazor Server**：浏览器的选文件夹对话框拿不到真实路径，而 Roslyn 需要真实路径。WPF 窗口可以直接用 Windows 自己的文件夹对话框。
- **不用 `Microsoft.Build.Locator`**：Roslyn 4.9 起，`MSBuildWorkspace` 会自己启动一个 BuildHost 进程，并在里面找 MSBuild。所以 `Microsoft.CodeAnalysis.Workspaces.MSBuild` 在 Core 里用 `PrivateAssets="none"` 引用，确保 BuildHost 的文件被复制到程序的输出文件夹。
- **目标框架是 `net10.0-windows10.0.19041.0`**：.NET 10 的 BlazorWebView 用到的 WebView2 控件要加载 `Microsoft.Windows.SDK.NET`，只写 `net10.0-windows` 时这个程序集不会带上，程序一启动就崩溃。
- **一个 HTML 文件，不依赖网络**：查看器的 CSS、JS 和数据都内嵌在文件里，没有外部字体和库，方便离线打开和分享。
- **界面用词**遵循全局词汇表（`GLOSSARY.md` 的 "Code Graph Generator" 一节），每个术语都带 `{标准术语}: {解释}` 的提示。
